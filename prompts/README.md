# Prompt library

Copy a prompt, fill in its bracketed details, and remove constraints that do not apply. These are starting points; repository guidance and your task context matter more than prompt wording.

| Recipe | Use it when |
| --- | --- |
| [Get oriented](get-oriented.md) | You are new to a repository or want a read-only overview |
| [Plan a change](plan-change.md) | The task crosses several areas or has open design questions |
| [Implement a change](implement-change.md) | The goal and acceptance criteria are clear |
| [Debug a problem](debug-problem.md) | You can describe a failure or reproduce it |
| [Review a diff](review-diff.md) | You want an independent review without edits |
| [Improve documentation](improve-documentation.md) | A guide is missing steps or confusing to new contributors |
| [Prepare a release](prepare-release.md) | You need a release checklist without publishing yet |
| [Security review](security-review.md) | You want a focused review of a change or area |

## A useful task description

Include the details that apply:

- **Goal:** the outcome you want.
- **Context:** existing behavior, affected area, or relevant constraints.
- **Acceptance:** how you will recognize a complete result.
- **Checks:** the project checks that matter, if known.

Keep credentials and sensitive data out of prompts. Use placeholders for examples.
